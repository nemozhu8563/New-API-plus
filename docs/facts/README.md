# 项目事实规范

`docs/facts/` 是一套可直接放入具体项目的事实规范和事实目录骨架。规则和模板都在本目录内；复制后，每个项目只维护自己的事实内容。

本目录可以作为一个整体复制到其他项目，不依赖其他工作流目录、自动化工具或特定技术栈。

## 目录组成

| 文件 | 用途 |
| --- | --- |
| `AGENTS.md` | Agent 处理本目录时必须遵守的操作入口。 |
| `STANDARD.md` | Facts 的完整、唯一规范正文。 |
| `current-system.md` | 项目当前状态总览、事实索引、范围映射和冲突入口。 |
| `architecture.md` | 技术栈、模块边界、运行方式、共享契约和数据流。 |
| `product-domain.md` | 业务对象、规则、状态、权限和业务不变量。 |
| `ui-style.md` | 全局界面、交互、视觉和组件约束。 |
| `integrations.md` | 外部服务、第三方接口、凭据来源和网络边界。 |
| `deployment.md` | 环境、数据库、迁移、备份、运维和回滚事实。 |
| `verified-commands.md` | 已从目标项目确认并实际验证的命令。 |
| `scopes/` | 多项目、多服务、多应用或多技术栈的范围事实。 |

## 放入新项目后

1. 保留 `AGENTS.md` 和 `STANDARD.md`，它们共同构成项目内的 Facts 规则。
2. 检查目标项目的代码、测试、配置、持续集成和实际运行状态。
3. 先填写 `current-system.md` 的事实索引和范围映射，再更新相应分类文件。
4. 无法确认的内容保留为“待定”；明确不适用的分类标记为“不适用”并写明依据。
5. 多项目、多服务或多技术栈时，在 `scopes/` 下创建稳定范围文件；普通单项目不需要为了完整而创建范围文件。
6. 项目出现新的稳定事实领域时，可以新增分类文件，但必须在 `current-system.md` 中登记，并遵守 `STANDARD.md` 的单一落点规则。

不要把提供这套规范的源项目内容复制成目标项目事实。Facts 必须由目标项目自己的证据建立。

## 项目级入口

目录本身是完整复制单元。若目标项目使用根目录 `AGENTS.md` 管理日常开发，建议只增加下面这段 Facts 入口，让代码变更和事实维护建立联系：

```markdown
- 判断项目当前状态前，先读 `docs/facts/current-system.md` 及其索引指向的相关事实文件，并用当前代码、测试、配置或运行结果复核。
- 读写 `docs/facts/**` 前，先读 `docs/facts/AGENTS.md`。
- 经验证的当前系统事实发生变化时，同步更新 `docs/facts/`；未知项保留“待定”，不得把计划写成事实。
```

这段入口只接入 Facts，不要求目标项目采用其他研发流程。没有根目录 `AGENTS.md` 的项目，仍可把本目录作为人工维护规范使用。
