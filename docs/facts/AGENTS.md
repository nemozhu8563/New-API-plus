# docs/facts 操作规则

本目录记录当前系统事实，并作为可随 `docs/facts/` 一起放入具体项目的自包含规范。完整规则见 `docs/facts/STANDARD.md`。

## 读取规则

- 处理 `docs/facts/**` 前先读本文件和 `docs/facts/STANDARD.md`。
- 再读 `docs/facts/current-system.md`，根据索引读取相关分类文件和范围文件。
- 需要形成或更新事实时，继续读取支撑主张的代码、测试、配置、命令或运行结果。
- 不能确认的内容标记为“待定”；来源互相矛盾时标记为“冲突”。

## 文件职责

- `current-system.md`：总览、索引、范围映射、当前阶段摘要和最大待确认事项。
- `architecture.md`：技术栈、模块边界、运行方式、共享契约位置和主要数据流。
- `product-domain.md`：跨范围共同成立的业务对象、业务规则、状态语义、权限语义和业务不变量。
- `ui-style.md`：全局界面风格、交互原则、视觉约束和组件库使用边界。
- `integrations.md`：外部服务商、第三方接口、账号能力、假实现、沙箱和真实接入边界。
- `deployment.md`：部署方式、环境、数据库、迁移、备份、运维和回滚约束。
- `verified-commands.md`：已确认命令、命令来源、适用范围、最近验证结果和待确认命令。
- `scopes/<范围名>.md`：具体子项目、服务、应用或共享包如何承载、呈现、执行和验证全局事实。

## 落点规则

- 全局状态、事实索引和范围映射写入 `current-system.md`。
- 横向事实写入对应分类文件。
- 子项目事实写入 `scopes/<范围名>.md`。
- 规则本身写入横向分类文件；某个范围如何实现、展示、调用或验证该规则，写入范围文件。
- 同一事实不要多处完整复制；非主位置只引用主位置。

## 写入门禁

写入前必须确认：

- 内容描述的是当前状态，不是未来意图或执行步骤。
- 作用范围明确。
- 有可复核来源，且表述没有超出来源能够证明的范围。
- 已选择唯一主文件，并检查了重复或冲突表述。

写入后必须同步受影响的索引、范围映射、刷新记录和冲突入口，并检查引用仍然有效。

## 范围事实规则

单仓多项目、多服务或多技术栈项目应使用 `scopes/`。

每个范围文件回答：

- 这个范围对应哪个路径。
- 这个范围使用什么技术栈及版本。
- 它如何承载全局业务规则、界面规则、外部服务或部署约束。
- 它有哪些当前实现、接口、页面、集合、命令和验证状态。
- 它有哪些待确认事实和已知约束。

不要在范围文件里重新定义全局业务规则；全局规则写入 `product-domain.md`。

稳定事实领域无法由标准文件承载时，可以新增职责单一的分类文件。新增文件必须在 `current-system.md` 登记，不得按变更、人员、分支或一次性任务命名。

## 禁止事项

- 不得创建 `docs/facts/chg-*`。
- 不得把未来计划、愿望、建议或执行步骤写成当前事实。
- 不得把截图、日志、测试报告全文写入 facts。
- 不得记录密钥、令牌、密码、Cookie、私钥或完整连接串。
- 未知命令写“待定”。
